# Vite

## Install

```bash
npm install @knitui/core @knitui/components @knitui/plugins \
  react-native-web react-native-reanimated react-native-worklets
```

## Configure

```ts title="vite.config.ts"
import { knitui } from "@knitui/plugins/vite";
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react(), knitui()],
});
```

`knitui()` is Tamagui v3's Vite plugin (`tamaguiPlugin` from `@tamagui/cli/vite`)
with the kit's config and component list baked in. It sets the pieces Vite does
not do on its own:

- `process.env.TAMAGUI_TARGET = "web"` and `__DEV__`;
- react-native platform extensions with `.web.*` preferred, so packages like
  `expo-image` resolve their web build instead of Flow-typed native internals;
- the `react-native` → `react-native-web` alias for the bare imports that remain;
- build-time style extraction, re-evaluating the config on save in development.

The plugin is **ESM-only** and has a **Vite 8** peer: keep `"type": "module"` in
`package.json`, or name the config `vite.config.mts`. Pass compiler options
through: `knitui({ disableExtraction: true })`. Run a build with
`TAMAGUI_COMPILER_STATS=verbose` to see what was flattened and what bailed.

<Callout>
  `TAMAGUI_IGNORE_BUNDLE_ERRORS` is a Tamagui v2 variable; v3 does not read it.
  When a module cannot be evaluated the compiler skips it quietly and falls back
  to runtime styling. `DEBUG=tamagui` lists what it skipped.
</Callout>

## Mount

```tsx title="src/main.tsx"
import { Provider } from "@knitui/core";
import { createRoot } from "react-dom/client";

import { App } from "./App";

createRoot(document.getElementById("root")!).render(
  <Provider defaultColorScheme="system">
    <App />
  </Provider>,
);
```

## Reanimated on the web

reanimated 4's web entry pulls a few CommonJS dependencies that need interop. If
you see `"no export default"` from inside reanimated, add them to the optimizer:

```ts
optimizeDeps: {
  include: ["react-native-reanimated", "react-native-worklets"],
}
```

## Storybook

The same configuration works under `@storybook/react-vite` — this repo's own
per-package Storybooks are set up exactly this way, so
[`.storybook/main.ts` in `@knitui/components`](https://github.com/the-haus/knitui/blob/main/packages/components/.storybook/main.ts)
is a working reference.

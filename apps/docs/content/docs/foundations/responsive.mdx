# Responsive

## Breakpoints

<BreakpointTable />

They come from the config, so [`createTheme({ breakpoints })`](/docs/foundations/theme-builder)
rebuilds the media queries and every consumer follows.

## Media clauses

A breakpoint is a **modifier inside the value** of the property it changes:

```tsx
<Box p="sm gtMd:lg" flexDirection="column gtSm:row" display="none gtXs:flex" />
```

Two families come from the config:

- `xs:` … `xl:` match **at or below** that breakpoint (`max-width`);
- `gtXs:` … `gtXl:` match **above** it (`min-width`).

So a mobile-first value reads as "base, then `gt…:` overrides as the viewport
grows". When the base or a breakpoint value is computed, use the object form:

```tsx
<Box p={{ default: compact ? "xs" : "sm", gtMd: "lg" }} />
```

Clause order does not matter, and state clauses (`hover:`, `press:`, `focus:`,
`disabled:`) outrank media clauses. v2's media props (`$sm={{ … }}`,
`$gtMd={{ … }}`) are gone.

Container queries work the same way against the nearest element marked
`container`: `w="100% @sm:50%"`.

## In JavaScript

```tsx
import { useMedia } from "@knitui/core";

function Nav() {
  const media = useMedia();
  return media.gtSm ? <Sidebar /> : <Drawer />;
}
```

`useMedia` is reactive on both platforms — on native it tracks the window
dimensions, on the web it uses `matchMedia`.

<Callout kind="warning">
  Rendering *different components* per breakpoint means remounting when the
  viewport crosses it, which loses state. Prefer styling one tree responsively
  and reserve component swaps for genuinely different UIs, like nav.
</Callout>

## SSR-safe queries

Server rendering has no viewport, so a naive `matchMedia` read produces a
hydration mismatch. [`@knitui/mediaquery`](/docs/mediaquery/playground) exists for
that case:

```tsx
import { MediaQueryProvider, useMediaQuery } from "@knitui/mediaquery";

// seed from the request's user agent so the first paint is close
<MediaQueryProvider userAgent={headers().get("user-agent")}>
```

```tsx
const isWide = useMediaQuery("(min-width: 992px)");
```

On native it parses the query and answers from `Dimensions`, so the same call
works on device.

## Viewport and element size

```tsx
import { useElementSize, useViewportSize } from "@knitui/hooks";
```

- [`useViewportSize`](/docs/hooks/use-viewport-size) — window dimensions, both
  platforms.
- [`useElementSize`](/docs/hooks/use-element-size) — an element's measured box.

<Callout kind="platform">
  On the web `useElementSize` returns a **callback ref**, not a one-shot effect
  observer — attach it to the element rather than reading a ref in an effect, or a
  node that mounts later never gets measured.
</Callout>

## Orientation and platform

```tsx
import { useOs } from "@knitui/hooks";

const os = useOs(); // "ios" | "android" | "macos" | "windows" | "linux" | "web" | undefined
```

Use it for genuine platform affordances (keyboard hints, store links), not for
layout — layout should follow size, not OS.
